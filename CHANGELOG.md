## [Unreleased]

Research layer: a fully reproducible study pipeline built on top of the prototype,
plus the publication scaffolding. Every reported number is regenerated by
`scripts/repro.ps1`; nothing is entered by hand.

### Added (2026-10)

- **Per-patient probability artifact** (`probabilities.csv`): the study runner now
  writes the open and the encrypted probability for every validation patient
  (`patient_index, eta_open, p_open, p_encrypted, decision_open, decision_encrypted`),
  which makes the “encrypted vs open” scatter plot reproducible straight from
  artifacts.
- **Single-pipeline scalability test up to 120,000 profiles** (`configs/study.json` →
  `results/20261015-052701_c4a6a8f1/`): the sensitivity control and the scalability
  measurement now run in one study run, so the manuscript draws every number from a
  single canonical run. Measured (median of 3 repeats): 2.3 s (1,000) / 2.2 s
  (8,000 — one batch) / 10.9 s (40,000) / 21.9 s (80,000) / 32.7 s (120,000), i.e. a
  constant ≈2.2 s per batch; memory, not time, is the limit on a 6 GB machine.
- **Sensitivity control for the disagreement metric** (`negative_control` in
  `src/study.rs` and in run artifacts): a neutral run, additive probability shifts
  `±Δp`, polynomial degradation, and extreme-but-valid profiles beyond the
  guarantee boundary `B` (binary features fixed to their extreme values); each run
  reports the plaintext-expected count and the observed homomorphic count, with a
  false-positive / false-negative split for the boundary scenario.
- **New canonical study run** `results/20261015-052701_c4a6a8f1/` — the run whose
  numbers the manuscript cites (timing table up to 120,000 profiles included). The
  wording "two independent runs / 73 exact invariants" was replaced by "the
  exact-invariant list is defined by `scripts/compare_runs.py`".
- Publication metadata: `Cargo.toml` now carries `repository`/`keywords`/etc.;
  `README.md` documents licensing/citation and the mapping between the prototype
  role CLIs and the two-party scenario evaluated in the manuscript.

### Added (2026-09)

- **Study runner** (`src/study.rs`, `src/bin/study.rs`): one call runs the whole
  protocol — synthetic cohort, reference model, polynomial construction, the
  homomorphic circuit in two modes, accuracy/agreement/equivalence analysis,
  scalability measurement, a determinism check, and artifact writing.
- **Deterministic synthetic cohort** (`src/cohort.rs`) with a documented
  data-generating process: covariates from declared distributions, true logit
  `η = β₀ + Σ βⱼxⱼ`, outcome `y ~ Bernoulli(σ(η))`, and the intercept `β₀`
  **calibrated by bisection** to a target prevalence instead of being hand-tuned.
- **Deterministic numerics without platform `libm`** (`src/detmath.rs`, `src/rng.rs`):
  own `exp`, `ln` and `cos` built from IEEE-754-specified operations, and
  `xoshiro256**` seeded through `SplitMix64` with named substreams, so cohort
  generation is bit-reproducible across machines.
- **Homomorphic logistic regression** (`src/he.rs`): standardised features are
  encrypted by the laboratory; the server evaluates the linear logit
  (`EvalMultPlain` + `EvalAdd`) and then a polynomial approximation of the sigmoid
  using ciphertext-by-ciphertext multiplication, followed by proxy re-encryption to
  the hospital key.
- **Polynomial sigmoid with a verified correctness criterion** (`src/poly.rs`): the
  approximation is **odd** — so `p(0) = 1/2` exactly — and is numerically verified to
  **preserve the sign relative to the decision threshold** on a dense grid and on the
  actual logits. Oddness plus sign preservation makes the binary classification
  identical to the plaintext rule `η ≥ 0` for *any* approximation error: the error
  shifts the reported probability, never the decision. Degree selection follows a
  pre-specified rule (smallest degree in the swept set that preserves the decision and
  meets a probability-error target).
- **Reported negative result**: requiring non-negative monomial coefficients (which
  would give monotonicity) is *harmful* on a wide interval — it raises the probability
  error from ≈4·10⁻³ to ≈10⁻¹, because the sigmoid is nearly a step there and its odd
  expansion alternates in sign. Monotonicity and coefficient signs are therefore
  measured and reported, not enforced.
- **Statistics implemented in-repository** (`src/stats.rs`), with no external
  statistical packages: Mann–Whitney AUC with the DeLong interval, Wilson and exact
  Clopper–Pearson intervals (including the rule of three), Cohen's kappa, exact
  McNemar, MCC/F1, Brier score, logistic recalibration, percentile bootstrap, and the
  Acklam normal quantile. Each procedure is covered by a test against a published or
  analytically derived reference value.
- **Reproducibility infrastructure**: a self-contained SHA-256 (`src/hash.rs`), an
  environment fingerprint capturing the compiler version, platform, CPU count, OpenFHE
  prefix and git revision (`src/env.rs`), and a manifest of SHA-256 digests for every
  artifact of a run.
- **Two independent study runs** shipped under `results/`, plus
  `scripts/compare_runs.py`, which classifies quantities as exact invariants,
  absolutely bounded (pure CKKS noise) or relatively bounded (approximation error
  dominates). Comparing the two runs shows 73/73 exact invariants matching, including
  a bit-identical `cohort.csv` hash; only CKKS-noise-level digits and timings differ.
- **Publication scaffolding**: `LICENSE` (BSD-2-Clause), `CITATION.cff`,
  `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `Makefile`, GitHub Actions
  workflow, `scripts/setup-openfhe.ps1`, `scripts/repro.ps1`,
  `scripts/validate_metadata.py`, `.editorconfig`, `.gitattributes`.
- **Vendored OpenFHE patch set** (`patches/openfhe-1.5.1-msvc.patch`): the MSVC /
  clang-cl compatibility fixes were previously only present inside the git-ignored
  `vendor/` tree, which made a clean rebuild impossible. The patch is validated by
  reverse-applying it to the patched tree.
- **Documentation**: `docs/STUDY_PROTOCOL.md`, `docs/DATA_FLOW.md` (with
  `docs/figures/data_flow.svg`), `docs/THREAT_MODEL.md`, `docs/DATA_DICTIONARY.md`,
  `docs/REPRODUCIBILITY.md`, `docs/REPORTING_GUIDELINES.md`.

### Changed

- `build.rs` resolves the OpenFHE prefix relative to `CARGO_MANIFEST_DIR` instead of
  an absolute path, records the compiler version and OpenFHE prefix into the binary
  for the environment fingerprint, and silences the unused-parameter warnings emitted
  by OpenFHE headers (408 warnings → 3).
- Tests that need a working directory write into `target/` rather than the system
  temp directory, so they do not depend on how `TEMP` happens to be configured.
- `README.md` documents the research layer and no longer claims that a separate patch
  file is unsupported.

### Fixed

- CI triggered only on `main` while the default branch is `master`, so it never ran;
  both branches are now listed.
- CI did not export `CLANGCL` / `CLANG_RT_DIR`, so the Rust build could not find the
  `clang-cl` installed by the runner.
- `CITATION.cff` described only the linear scoring path; the abstract now covers the
  logistic circuit, the study runner and the reproducibility artifacts.

### Notes

- The threshold **comparison** is performed by the hospital in the clear, on the
  decrypted probability. The probability itself — including crossing the threshold —
  is computed homomorphically. Because the threshold is public, the comparison adds no
  information beyond the probability; hiding the probability too, leaving only a
  decision bit, would require a homomorphic comparison circuit (FHEW/TFHE scheme
  switching) and is listed as future work.
- The manuscript draft lives in `paper/`, which is deliberately git-ignored.

## [0.1.0] - 2026-09-07

First public release: a research prototype of privacy-preserving type-2-diabetes
risk scoring under homomorphic encryption.

### Added

- Rust crate `hepre` wrapping OpenFHE 1.5.1 through a `cxx` bridge, with a C++ FFI
  shim (`cpp/openfhe-shim.cc`) compiled by `build.rs` with `clang-cl` and linked
  against the static OpenFHE libraries plus `clang_rt.builtins-x86_64`.
- Two homomorphic backends: CKKS (approximate arithmetic, batch 8192, depth 2,
  scaling modulus size 40) and BFV (integer arithmetic, plaintext modulus 65537).
- Lattice proxy re-encryption in the INDCPA-PRE mode (`Enable(PRE)` +
  `SetPREMode(INDCPA)`), exposing `ReKeyGen` and `ReEncrypt` through
  `Context::rekeygen` / `Context::reencrypt`.
- Persistent error handling at the FFI boundary: every shim function traps C++
  exceptions with the `guard<>` template, stores `e.what()` in a thread-local slot
  and returns a sentinel, which the Rust side turns into `Result<T, Error>` instead
  of letting an exception cross the bridge and abort the process.
- RAII handles for contexts, key pairs, public/secret/evaluation keys, plaintexts
  and ciphertexts — every OpenFHE object is owned by a Rust type and released in
  `Drop`.
- Binary serialization of public keys, secret keys, re-encryption keys and
  ciphertexts, used for the file-based handoff between roles.
- Three separate role CLIs with a file-based handoff over the `handoff/` directory:
  `lab` (generates keys, encrypts patient features, issues the re-encryption key),
  `server` (evaluates the score homomorphically and re-encrypts it, holding no
  decryption key) and `hospital` (key generation, decryption, thresholding).
- End-to-end linear risk scoring: `score_i = Σ_j w_j·x_ij + b` computed with
  `EvalMultPlain` + `EvalAdd` + `EvalAddPlain` (additive circuit, no `Rescale`),
  followed by proxy re-encryption of the score to the hospital key.
- `scoring` module with `ScoringModel` and plaintext reference implementations
  (`score_plain` / `predict_plain`) for accuracy comparison in tests and benchmarks.
- Integration test suite of 15 tests across `tests/ckks.rs`, `tests/bfv.rs`,
  `tests/pre.rs`, `tests/serialize.rs`, `tests/score.rs` and
  `tests/roles_handoff.rs`, including a cross-process run of the three role CLIs.
- `examples/bench.rs` benchmark binary measuring the end-to-end scoring pipeline.
- Windows build tooling and helper scripts for configuring and building the
  vendored OpenFHE tree with `clang-cl`, `CMake` and `NMake`.

### Security

- The prototype is intended for research and reproducibility only. It is not
  production cryptography: it must not be used with real patient data. Known
  limitations (single global mutex serialising all OpenFHE calls, INDCPA-PRE mode
  only, no side-channel hardening, no key management, no audit trail) are
  documented in `SECURITY.md`.
