# Словарь данных (Data Dictionary) — HEPRE

> ## ⚠️ Дисклеймер
>
> **Когорта полностью синтетическая. Реальные данные пациентов не используются** — ни в
> репозитории, ни в тестах, ни в демонстрационных утилитах. Персональные данные и ФИЗ в проекте
> отсутствуют (см. также `SECURITY.md`: прототип нельзя применять к реальным персональным данным).
>
> Переменные и их распределения выбраны так, чтобы быть **клинически правдоподобными** (типовые
> рутинные лабораторные и антропометрические предикторы диабета 2-го типа), а **не** чтобы
> воспроизводить какую-либо конкретную популяцию, регион, лабораторию или опубликованную когорту.
> Это прямо зафиксировано в комментарии к `default_t2dm_config()` (`src/cohort.rs`).
>
> Числа в §2 и §3 — это **фактические значения по умолчанию из кода**, а не описательные
> статистики какой-либо выборки. Они задают процесс порождения данных (DGP) и подлежат изменению
> только через конфигурацию прогона с фиксацией в `results/<run-id>/manifest.json`.

## 1. Происхождение и статус данных

| Вопрос | Ответ |
|---|---|
| Источник | Синтетический генератор `src/cohort.rs` (`Cohort::generate`, конфигурация `default_t2dm_config()`) |
| Реальные пациенты | Нет |
| Персональные данные / ФИЗ | Нет |
| Эталон («ground truth») | Задаётся явно: истинный логит `η_i = β₀ + Σ_j β_j·x_ij` и истинная вероятность `p_i = σ(η_i)` сохраняются **вместе** с данными; наблюдённый исход `y_i ~ Bernoulli(p_i)` |
| Воспроизводимость | Бит-в-бит: целочисленный PRNG `xoshiro256**` (инициализация `SplitMix64`, `src/rng.rs`) + детерминированная математика `src/detmath.rs` (собственные `exp`/`ln`/`cos`, `sqrt` из `std` как корректно округлённый по IEEE-754) |
| Разбиение | `derivation` («обучающая») и `validation` («валидационная») части; перемешивание Фишера—Йетса отдельным подпотоком ПРНГ |
| Артефакт | `results/<run-id>/cohort.csv` (`Cohort::to_csv`), модели — `model.json`, метрики — `results.json` |
| Назначение | Методологическое исследование **криптографического** прототипа и воспроизводимая оценка его численных свойств; не клинические выводы |

| Параметр | Значение |
|---|---|

| `n_derivation` | `8 000` |

## 2. Набор признаков (предикторы)

Набор моделирует **рутинные клинико-лабораторные и антропометрические предикторы сахарного
диабета 2-го типа**. Все семь переменных — предикторы; целевая переменная порождается моделью
(§2.3), а не берётся из внешних данных.

| Переменная (`name`) | Единицы | Описание | Распределение ковариаты | Усечение `[min, max]` | `beta_true` |
|---|---|---|---|---|---|
| `hba1c_pct` | `%` | Гликированный гемоглобин HbA1c | `Normal { mean: 5.6, sd: 0.85 }` | 4.0 … 14.0 | `1.10` |
| `fasting_glucose_mmol` | `ммоль/л` | Глюкоза плазмы натощак | `Normal { mean: 5.4, sd: 1.10 }` | 3.0 … 20.0 | `0.45` |
| `triglycerides_mmol` | `ммоль/л` | Триглицериды | `Normal { mean: 1.7, sd: 0.85 }` | 0.3 … 12.0 | `0.30` |
| `hdl_mmol` | `ммоль/л` | Холестерин липопротеинов высокой плотности | `Normal { mean: 1.40, sd: 0.35 }` | 0.4 … 3.2 | `-0.60` |
| `bmi` | `кг/м²` | Индекс массы тела | `Normal { mean: 27.5, sd: 5.0 }` | 15.0 … 55.0 | `0.07` |
| `age_years` | `годы` | Возраст | `Normal { mean: 52.0, sd: 13.0 }` | 18.0 … 90.0 | `0.035` |
| `family_history` | `0/1` | Семейный анамнез диабета | `Bernoulli { p: 0.30 }` | — (игнорируется) | `0.75` |

Точные типы (`src/cohort.rs`): `Distribution::Normal { mean, sd }` и `Distribution::Bernoulli { p }`.
Непрерывные признаки порождаются **усечённым нормальным** распределением (отбраковка до 1000
попыток, затем `clamp` в границы — процедура детерминирована и гарантированно завершается).
Логнормальных и иных скошенных семейств в коде **нет**; «правдоподобный физиологический диапазон»
здесь совпадает с границами усечения `min`/`max` и проверяется тестом
`features_respect_declared_bounds`.

`beta_true` — истинные коэффициенты порождающей логистической модели, заданные как **лог-отношения
шансов на нативную единицу признака** (`%`, `ммоль/л`, `кг/м²`, годы).

### 2.1 Стандартизация признаков (обязательное условие)

Эталонная модель исследования (`src/logistic.rs`) обучается на **стандартизованных** признаках:
`z_j = (x_j − mean_j) / sd_j`; средние и СКО — публичные метаданные модели
(`LogisticModel::standardization_metadata`, поля `means`/`sds`), они передаются лаборатории вместе
с весами. Обоснование в коде: масштаб значений определяет точность CKKS, поэтому центр и разброс
приводятся к единому виду, а интерцепт впитывает сдвиг. Именно линейную форму
`η = b + Σ_j w_j·z_j` вычисляет сервер гомоморфно
(`LogisticModel::eta_standardized`).

Практические следствия:

- в `cohort.csv` хранятся **сырые** значения в единицах из §2; стандартизация — часть модели, а не
  данных;
- отношения шансов возвращаются к нативным единицам как `OR_j = exp(w_j / sd_j)`
  (`odds_ratios_per_unit`);
- решающее правило — знак логита: `predict = (η ≥ 0)`, что эквивалентно `p ≥ 0.5`
  (`LogisticModel::predict`). Это принципиально: полиномиальная аппроксимация сигмоиды
  (`src/poly.rs`) не влияет на бинарное решение, только на сообщаемую вероятность.

### 2.2 Отдельный демонстрационный контур (5 признаков)

CLI-утилиты ролей и `examples/bench.rs` используют компактный **5-признаковый нормированный**
набор — это пример, а не набор исследования:

| Место | Признаки | Модель |
|---|---|---|
| `src/demo_common.rs` (`Model::default`), `README.md` §«Пример», `tests/roles_handoff.rs` | 5 нормированных: `[hba1c, glucose, bmi, age, family]` | `weights = [0.22, 0.14, 0.08, 0.03, 0.10]`, `intercept = -1.70`, `threshold = -1.45` |
| `examples/bench.rs` | 5 нормированных: `[age, bmi, glucose, family_hist, hba1c]` (другой порядок!) | `weights = [0.03, 0.08, 0.14, 0.10, 0.22]`, `intercept = -1.7`, `threshold = 0.0` |
| `tests/score.rs` | 3 безразмерных признака | `weights = [0.4, -0.2, 0.7]`, `intercept = 0.1`, `threshold = 0.5` |

**Порядок признаков задаётся порядком `weights`** — заголовка признаков в контейнере нет (§5),
поэтому перепутанный порядок не обнаруживается: `server.rs` проверяет только `f == weights.len()`.

### 2.3 Порождающая модель исхода

```text
η_i = β₀ + Σ_j β_j · x_ij          (β₀ калибруется бисекцией)
p_i = σ(η_i) = 1 / (1 + e^{−η_i})   (детерминированная σ из src/detmath.rs)
y_i ~ Bernoulli(p_i)                (наблюдённый исход)
```

Сохраняются `eta_true`, `p_true` и `outcome`, поэтому любая модель может быть сопоставлена не
только с разметкой, но и с истинной вероятностью. Распространённость исходов регулируется
`target_prevalence` (по умолчанию `0.12`), а не подбирается «на глаз».

## 3. Файлы модели

### 3.1 `model.json` — модель для CLI-утилит ролей

Схема `Model` реализована в `src/demo_common.rs` (serde) и дублируется в `src/scoring.rs`
(`ScoringModel`).

| Поле | Тип JSON | Обязательно | Смысл | Ограничения |
|---|---|---|---|---|
| `weights` | массив `number` (f64) | да | Веса предикторов; порядок = порядок колонок признаков | Длина должна совпадать с `f` из контейнера признаков (`server.rs` проверяет; `compute_score` возвращает `Err` при несовпадении) |
| `intercept` | `number` (f64) | да | Свободный член `b` | Аддитивный контур A2, `Rescale` не применяется |
| `threshold` | `number` (f64) | да | Порог бинарного риска, применяется **больницей в открытом виде** | `risk = score >= threshold` (`ScoringModel::predict_plain`, `hospital.rs`) |

Все три поля обязательны (у `Model` нет `#[serde(default)]`); лишние поля `serde_json` игнорирует.
Модель **публична по построению**: передаётся и лаборатории, и серверу аргументом `--model`;
коммитмента/подписи нет (`docs/THREAT_MODEL.md`, актив A3 и риск M1).

Пример (`Model::default`, он же в `README.md`):

```json
{"weights":[0.22,0.14,0.08,0.03,0.10],"intercept":-1.70,"threshold":-1.45}
```

### 3.2 `LogisticModel` — обученная эталонная модель исследования

`src/logistic.rs`: подгонка методом Ньютона—Рафсона (IRLS) с L2-регуляризацией (интерцепт штрафом
не облагается), решение линейной системы — методом Гаусса с выбором ведущего элемента, шаг
останавливается по критерию сходимости.

| Поле | Смысл |
|---|---|
| `feature_names` | Имена признаков в порядке столбцов |
| `weights` | Веса по стандартизованным признакам `z_j` |
| `intercept` | Логит при `z = 0` (то есть при средних значениях признаков) |
| `means`, `sds` | Средние и СКО признаков на обучающей выборке (публичные метаданные) |
| `lambda` | Коэффициент L2-регуляризации |
| `iterations`, `converged` | Число шагов Ньютона и признак сходимости |
| `n_train`, `n_events` | Размер обучающей выборки и число событий |

### 3.3 `SigmoidPolynomial` — приближение сигмоиды для гомоморфного контура

`src/poly.rs`: аппроксимируется нечётная функция `σ(η) − 1/2` многочленом по нечётным степеням
`u = η/B`, коэффициенты считаются через разложение по многочленам Чебышёва, вычисление —
схемой Патерсона—Стокмейера (`select_evaluation_scheme`).

| Поле | Смысл |
|---|---|
| `bound` | Граница аппроксимации `B` (`\|η\| ≤ B`) |
| `power` | Старшая нечётная степень `P` |
| `coeffs` | Коэффициенты `d_k` при `u^{2k+1}` |
| `all_coefficients_nonnegative`, `min_derivative_positive_side`, `monotone_positive_side`, `monotone_full` | Отчёт о структурных свойствах (неотрицательность коэффициентов ⇒ монотонность) |
| `max_abs_error`, `max_error_at`, `max_abs_error_on_data` | Ошибка аппроксимации на сетке и на фактических логитах |
| `mult_depth`, `block_size` | Мультипликативная глубина и размер блока схемы |

Структурное следствие (зафиксировано в документации модуля): при неотрицательных коэффициентах и
нечётности решение `p(η) ≥ 1/2` **тождественно** решению `η ≥ 0`, поэтому бинарная классификация не
зависит от точности аппроксимации.

## 4. Файл пациентов (`patients.json`) и когорта (`cohort.csv`)

### 4.1 `patients.json` — вход CLI-утилит ролей

Схема `Patient` реализована в `src/demo_common.rs`.

| Поле | Тип JSON | Обязательно | Смысл | Поведение при отсутствии |
|---|---|---|---|---|
| `name` | `string` | нет (`#[serde(default)]`) | Идентификатор пациента | Пустое имя заменяется на `P{i+1}` |
| `features` | массив `number` (f64) | да | Нормированные значения предикторов в порядке `weights` | Ошибка разбора |

Пример (`README.md` §«Пример использования»):

```json
{"name":"P1","features":[0.50,0.40,0.20,0.30,0.00]}
```

Правила ввода (`resolve_json_arg` / `parse_model` / `parse_patients`):

- аргумент `--patients`/`--model` — **либо** inline JSON-строка, **либо** путь к существующему файлу;
- внешние кавычки (`'`/`"`) вокруг аргумента снимаются;
- ведущий BOM (`U+FEFF`, PowerShell 5.1 `Set-Content -Encoding utf8`) отбрасывается перед разбором;
- число признаков `f` берётся из **первой** строки (`features.first()`); равенство длин у остальных
  пациентов **не проверяется**;
- отсутствующие значения признака трактуются как `0.0` (`encrypt_features`: `get(j).unwrap_or(0.0)`),
  лишние игнорируются — то есть **пропуски молча превращаются в нули**.

### 4.2 `cohort.csv` — когорта исследования (`Cohort::to_csv`)

Формат генерируется кодом; числа печатаются с 10 знаками после запятой, идентификаторы имеют вид
`S000000` (индекс в общем пуле).

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | строка `S{индекс:06}` | Идентификатор (синтетический) |
| `split` | `derivation` \| `validation` | Принадлежность к обучающей или валидационной части |
| `<name>` × 7 | f64 | Сырые значения признаков в порядке `CohortConfig::predictors` (§2) |
| `eta_true` | f64 | Истинный логит порождающей модели |
| `p_true` | f64 | Истинная вероятность `σ(η)` |
| `outcome` | `0`/`1` | Наблюдённый исход |

Порядок строк: сначала все `derivation`, затем все `validation`; внутри части — порядок после
перемешивания подпотоком `split`. Заголовок и число строк проверяются тестом
`csv_has_header_and_all_rows`.

## 5. Формат handoff-контейнера (как реализовано в `src/demo_common.rs`)

Ключи и шифротексты сериализуются OpenFHE в бинарном виде (`SerType::BINARY`) и заворачиваются в
небольшой контейнер. Ниже — точная раскладка `write_handoff`/`read_handoff`.

### 5.1 Заголовок и blob-ы

| Смещение (байт) | Тип | Поле | Значение / смысл |
|---|---|---|---|
| 0 | `u32` little-endian | `MAGIC` | `0x48504550` (константа `MAGIC`; в исходнике помечена комментарием `// "EHPE"`) |
| 4 | `u16` LE | `VERSION` | `1` |
| 6 | `u16` LE | `kind` | `0` = `KIND_FEATURES`, `1` = `KIND_SCORES` |
| 8 | `u32` LE | `n` | Число пациентов |
| 12 | `u32` LE | `f` | Число признаков; для контейнера скоров записывается `0` |
| 16 | `u32` LE | `n_blobs` | Число blob-ов |
| 20 | `u64` LE + байты | `blob[0]` … `blob[n_blobs-1]` | Длина blob-а (u64 LE), затем сами байты (OpenFHE BINARY), последовательно, без выравнивания |

Итого заголовок — **20 байт**; далее `n_blobs` пар «длина (u64) + данные». Порядок байтов —
little-endian (Windows x64); формат не портируем на big-endian без изменений.

### 5.2 Семантика контейнеров

| Контейнер | `kind` | `n` | `f` | Состав blob-ов | Кто пишет / читает |
|---|---|---|---|---|---|
| `features.cts.bin` | 0 | пациентов | признаков | `ceil(n / 8192) * f` шифротекстов: пакетами по 8192 пациента, внутри пакета — по одному шифротексту на признак в порядке `j = 0..f-1` | пишет `lab`, читает `server` |
| `scores.ct.bin` | 1 | пациентов | `0` | `ceil(n / 8192)` шифротекстов (по одному на пакет) | пишет `server`, читает `hospital` |

Проверки читателя (`read_handoff`, `server.rs`, `hospital.rs`): `MAGIC`; `VERSION == 1`; ожидаемый
`kind`; границы каждого blob-а (при усечении — ошибка); в `server.rs` дополнительно
`n_blobs == ceil(n/8192)*f` и `f == weights.len()`.

Чего в контейнере **нет** (важно для модели угроз): контрольной суммы, MAC, подписи, идентификатора
прогона, nonce, метки времени, имён/порядка признаков, единиц измерения и версии модели. Заголовок
можно изменить без обнаружения — см. `docs/THREAT_MODEL.md` §4.2 (M3), §7 (O6). Контрольные суммы
SHA-256 существуют только для **артефактов исследования** (`src/hash.rs`, манифест прогона), а не
для handoff-файлов.

### 5.3 Файлы, которые **не** используют контейнер

`hosp.pk.bin`, `hosp.sk.bin`, `rekey.ek.bin` записываются как «сырые» байты сериализации OpenFHE
(`serialize()` → `fs::write`), без заголовка `MAGIC`/version/kind; тип определяется операцией
чтения (`deserialize_public_key` / `deserialize_secret_key` / `deserialize_eval_key`).

| Файл | Что внутри | Где создаётся | Где читается |
|---|---|---|---|
| `hosp.pk.bin` | Публичный ключ больницы (OpenFHE BINARY) | `hospital keygen` | `lab encrypt --hospital-pk` |

## 6. Схема результатов прогона

Раскладка `results/<run-id>/` описана в `docs/REPRODUCIBILITY.md` §8. Фактические артефакты раннера
(`src/study.rs`) и их содержательная нагрузка:

| Артефакт | Что содержит |
|---|---|
| `manifest.json` | Перечень артефактов с SHA-256 и размерами, отпечаток среды, результат проверки детерминизма |
| `environment.json` | `EnvironmentFingerprint`: версия Rust, arch, ОС и её версия, число CPU, `OPENFHE_HOME`, версия крэйта, ревизия и ветка git, время запуска |
| `config.json` | Полная конфигурация `StudyConfig` (см. таблицу ниже) |
| `cohort.csv` | Когорта в формате §4.2 |
| `model.json` | Обученная модель (§3.2) с метаданными стандартизации (§2.1); в CLI-контуре тот же файл несёт `weights`/`intercept`/`threshold` (§3.1) |
| `roc_curve.csv` | ROC-кривая на валидационной выборке |
| `calibration_deciles.csv` | Калибровочные децили (наблюдаемая доля против предсказанной) |
| `polynomial_sweep.csv` | Таблица «точность против мультипликативной глубины» для аппроксимации сигмоиды |
| `polynomial_coefficients.csv` | Коэффициенты выбранного многочлена |
| `scalability.csv` | Замеры по размерам когорты (медиана по повторам) |
| `results.json` | Полный `StudyResults` (все посчитанные величины; сам себя не перечисляет) |

`StudyConfig` (`config.json`) состоит из подобъектов:

| Блок | Поля | Смысл |
|---|---|---|
| — | `study_name`, `design` | Имя и описание дизайна |
| `cohort` | `seed`, `n_derivation`, `n_validation`, `target_prevalence`, `prevalence_calibration_n`, `predictors[]` | Полностью определяет DGP (§1.1, §2) |
| `model` | `lambda`, `max_iter`, `tol` | L2-регуляризация, лимит шагов Ньютона, порог сходимости |
| `polynomial` | `sweep_powers[]`, `selected_power`, `bound_margin`, `min_bound` | Степени для развёртки, рабочая степень, запас к границе `B = max\|η\| · margin` |
| `evaluation` | `alpha`, `equivalence_margin`, `bootstrap_replicates`, `bootstrap_seed` | Уровень значимости, порог эквивалентности, параметры бутстрапа |
| `he` | `batch_size`, `scaling_mod_size`, `depth_margin` | Параметры CKKS-контекста (глубина выводится из многочлена + запас) |
| `scalability` | `sizes[]`, `repeats` | Размеры когорты и число повторов для замера |

Ожидаемые метрики (реализованы в `src/stats.rs`, вывод — `results.json`): AUC по Манну—Уитни с
доверительным интервалом ДеЛонга, ROC-кривая и порог Юдена,
чувствительность/специфичность/PPV/NPV/точность/F1/MCC, каппа Коэна, мера Бриера, калибровка
(наклон и свободный член логистической рекалибровки, децили), точный тест МакНемара, интервалы
Вильсона и Клоппера—Пирсона, процентильный бутстрап с явным семенем, проверка эквивалентности по
доле расхождений, а также погрешность гомоморфного контура и расхождения бинарных решений.
Конкретные значения здесь **не приводятся**: они появляются только в артефактах прогона
(`results/<run-id>/results.json`).

## 7. Пропуски, выбросы и качество данных

| Аспект | Как устроено сейчас | Комментарий |
|---|---|---|
| Пропуски в когорте | Отсутствуют **по построению**; в диагностике есть поле `missing_fraction` со значением `0.0` для каждого признака (`FeatureSummary`) | Это не «хорошее качество данных», а свойство синтетики — так и надо указывать в отчёте |
| Пропуски в CLI-контуре | `patients.json` подставляет `0.0` вместо отсутствующего признака (`unwrap_or(0.0)`) — дефект для реального применения; для HbA1c/ИМТ значение `0.0` физиологически невозможно | В проде требуется явная политика (исключение/импутация), зафиксированная в манифесте |
| Выбросы | Отбраковка при генерации: значение вне `[min, max]` не принимается (до 1000 попыток), затем `clamp`; тест `features_respect_declared_bounds` | Границы совпадают с диапазонами §2 |
| Единицы измерения | Явно заданы в спецификации предиктора (`units`), попадают в диагностику и CSV | Смешение единиц не детектируется — нормализация/стандартизация обязательна (§2.1) |
| Дубликаты | Не возникают: идентификаторы `S{i:06}` уникальны, разбиение — перестановка пула (тест `split_partitions_the_pool_without_overlap`) | — |
| Целостность артефактов | SHA-256 (`src/hash.rs`, тестовые векторы NIST) и digest-ы в манифесте | Handoff-файлы ролей **не** хэшируются и не аутентифицируются (§5.2) |

## 8. Что в словарь не входит

- **Реальный клинический исход.** `outcome` — синтетическая Bernoulli-величина из DGP, а не диагноз;
  метрики на ней характеризуют внутреннюю согласованность, а не клиническую точность
  (`docs/REPORTING_GUIDELINES.md`).
- Пол, этническая принадлежность, социально-экономические факторы, сопутствующая терапия — не
  моделируются, поэтому анализ подгрупп/fairness по ним невозможен.
- Реальные референсные интервалы конкретной лаборатории: диапазоны §2 — правила генерации
  и валидации.
- Ключевой материал и его сроки жизни/ротация — см. `docs/THREAT_MODEL.md`, активы A4–A7, и
  `SECURITY.md`.
- Правовые аспекты работы с данными: персональных данных нет, когорта синтетическая.
