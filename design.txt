ТЗ на научную статью (актуализировано под фактическую реализацию этапа A2).
Журнал уровня Q1–Q2 (например, Journal of Biomedical Informatics, IEEE Transactions on
Medical Imaging, International Journal of Medical Informatics).
Тема: «Применение гибридной схемы гомоморфного шифрования и прокси-перешифрования для
безопасного скоринга в клинической лабораторной диагностике».

Цель работы — разработать и продемонстрировать прототип системы, который позволяет:
1.  Лаборатории (или пациенту) зашифровать свои данные (результаты анализов) с помощью
    гомоморфного шифрования (HE).
2.  Серверу (агрегатору, страховой компании, исследовательскому центру) выполнять над
    зашифрованными данными вычисления непрерывного риска (например, риск-скора диабета
    2-го типа) без расшифровки исходных данных пациентов.
3.  С помощью прокси-перешифрования (PRE) предоставить больнице расшифровать только
    финальный риск-скор и применить бинарный порог в открытом виде — но не исходные
    данные и не промежуточные фичи.

Техническая реализация (фактический стек прототипа):
- Rust-обёртка (cxx bridge) над OpenFHE: схемы CKKS (вещественные фичи и скор) и BFV
  (целочисленный контрольный путь), решёточное прокси-перешифрование INDCPA-PRE
  (ReKeyGen / ReEncrypt) непосредственно в OpenFHE.
- Вся обработка C++-исключений — на границе FFI (Thread-local текущая ошибка +
  сентинельные значения); FFI сериализуется мьютексом (глобальные реестры OpenFHE
  не потокобезопасны). RAII-хэндлы в Rust.
- Прототип демонстрирует сквозной процесс:
  - генерация ключей (лаборатория, больница) и ключа перешифрования (lab_sk → hosp_pk);
  - SIMD-упаковка фичей пациентов лабораторией (пациент = слот, признак = шифротекст);
  - гомоморфный скор на сервере: score_i = Σ_j w_j·x_ij + b (EvalMultPlain + EvalAdd);
  - PRE-перешифрование скора сервером на ключ больницы;
  - расшифровка больницей своего скора и применение порога в открытом виде.

В качестве примера вычислений используется сценарий:
Страховой скоринг — расчёт бинарного риска (риск диабета 2-го типа) на основе
нормированных лабораторных показателей (HbA1c, глюкоза, ИМТ, возраст, семейный
анамнез) с линейной моделью и порогом.

Статистические методы сравнения (t-критерий Стьюдента Уэлча, z-оценка) НЕ реализованы:
в A2 решено ограничиться сквозным скорингом; порог применяется больницей на открытом
расшифрованном скоре, поэтому для сравнения используется согласованность бинарных
предсказаний HE-прототипа с открытой моделью.

План статьи:
1.  Введение (~1 стр.)
    - Мотивация: чувствительные лабораторные данные, инциденты утечек, необходимость
      обработки у агрегаторов без доверия.
    - ФИИС-совместимость (152-ФЗ) и роль HE+PRE: шифровать у источника, вычислять на
      сервере, выдавать только результат.
    - Вклады: end-to-end прототип, оценка точности и производительности, PRE для
      разделения «сервер считает / больница решает».
2.  Обзор литературы (~2 стр.)
    - FHE на практике: CKKS vs BFV (причины выбора CKKS для вещественных фич).
    - PRE: схемы решёточного прокси-перешифрования, IND-CPA, сравнение с классическими
      подходами (ключевые стороны/доверенный посредник).
    - Смежные работы: приватный скоринг в медицине (Benchmark OpenFHE/SEAL, 논문まで),
      разница: наш прототип на Rust + cxx, PRE внутри схемы (без сторонних PRE-библиотек).
3.  Материалы и методы (~3 стр.)
    3.1 Криптографический протокол:
        - Параметры: batch 8192, multiplicative depth 3, scaling 40 бит.
        - Роли: лаборатория (данные), сервер (FHE-вычисления), больница (расшифровка).
        - Поток: Lab.KeyGen → Lab.Enc(features) → Server.Score(Σ w·x + b) →
          Hospital.ReKeyGen(lab_sk → hosp_pk) → Server.ReEncrypt(score) →
          Hospital.Decrypt(score) → Hospital.Threshold(τ).
        - Модель угроз: получестный сервер; лаборатория не видит модель, сервер не
          видит ни данные, ни результат; больница видит только финальный скор.
    3.2 SIMD-упаковка: пациент в слоте, признак — отдельный шифротекст;
        Σ_j выполняется циклически по шифротекстам (без Rescale в аддитивном контуре).
    3.3 Обработка ошибок и безопасность границы вызова (Thread-local error, sentinel).
4.  Реализация (~2 стр.)
    - Rust cxx bridge, shim на C++ с guard<>/мьютексом, статическая сборка OpenFHE.
    - Карта FFI: контексты, ключи, plaintext/ciphertext, eval, PRE, сериализация.
    - Тестовый контур: 11 тестов A1 (BFV/CKKS/PRE/сериализация) + 3 теста A2 (скоринг).
5.  Эксперименты (~2 стр.)
    5.1 Производительность для N = 10/100/1000/10000 (чанки по 8192 слота):
        KeyGen, ReKeyGen, Encrypt, Score, PRE(ReEncrypt), Decrypt — Release-замеры
        std::time (см. examples/bench.rs).
    5.2 Точность: max|вещественная-ошибка| < 10⁻⁶ (фактически ~10⁻⁹), совпадение
        бинарных предсказаний с открытой моделью во всех размерах выборки.
    5.3 Масштабируемость: время растёт слабо до 8192 пациентов (одна SIMD-упаковка),
        далее линейно по числу пакетов.
6.  Обсуждение (~2 стр.)
    - Безопасность: правильный ключ расшифровывает, чужой ключ → мусор либо Err
      (fail-closed Decode); обсуждение IND-CPA.
    - Ограничения: аддитивный скор (без Rescale/длинных контуров) упрощает архитектуру;
      производительность растёт с batch; только линейные модели пока что.
    - Улучшения: нелинейные модели (сигмоида полиномиальной аппроксимацией, CKKS + Rescale),
      комбинация с ZKP для верификации корректности результата, многопартийный вариант.
7.  Заключение (~1 стр.)
    - Вклады: стек Rust+OpenFHE+cxx; сквозной скоринг с PRE; измеренные характеристики
      (KeyGen ~28мс, ReKeyGen ~38мс, Encrypt/Score/PRE/Decrypt на 10k ~221/155/39/70мс);
      точность ~10⁻⁹; направление будущей работы.
8.  Ключевые слова:
    fully homomorphic encryption, CKKS, proxy re-encryption, secure multi-party computation,
    clinical diagnostics, risk scoring, SIMD packing, Rust, OpenFHE.
